自然言語による TurtleBot3 巡回・指示灯確認の検証報告

実験日：2026-10-11。報告更新日：2026-11-01。対象：Gazebo内のTurtleBot3シミュレーション。

1. 目的・出典・構成

Qiitaの参考記事の自然言語→LLM→ROS 2→Gazeboという構成を基に、名前付き地点の順序実行、Nav2の実際の完了・到着確認、停止後のカメラによる赤緑判定を追加した。記事コードのライセンスを推定せず、参考構成として出典を示す。独自コードはApache-2.0、SafeDiffDriveとROBOTIS等の上流著作権・LICENSEは保持する。詳細はREADME、THIRD_PARTY_NOTICES、UPSTREAMに記録した。

Ubuntu 24.04、ROS 2 Jazzy、Gazebo Harmonic、TurtleBot3 Waffle Pi、Nav2をDockerで実行する。CPU4コア・8GiB、GPUなし、Mesa llvmpipeによる実カメラ描画である。実行時の仮想カメラは640×480・5simHz、lidarは10simHz。正式検証のimageはcae82b8e21c65fb49d5efbae6ce1fc6abd16f6c6a44554e775b7e2c7b755cf79。

入力文→真正なVertex GeminiのJSON計画→厳格な形式・意味検証→ROS Action→Nav2目標→実到着・停止確認→画像確認→残り手順、という順に処理する。モデルは座標・コード・shellを生成せず、最大8手順のnavigate_to、inspect_indicator、return_to_base、stopだけを返す。座標は人が設定し、base=(-3,-2,0)、A=(3,-2,0)、B=(3,2,π/2)である。

不明地点、曖昧な指示、既知と未知の混在は全体を拒否する。LLM呼出しは走行前に一度だけ行い、検証した元のモデル計画を実行する。ローカル生成の固定経路への置換、任意コード実行、認証失敗時の暗黙のstub切替はない。request_idはアプリ生成の相関UUIDであり、Vertex HTTP応答のrequest IDではない。原文・元JSON・検証済計画・Action UUID・Nav2 UUID・実使用量を結び付けて確認できる。

2. モデルの選定と効果の判断

現在の既定モデルはgemini-3.1-pro-preview/global、thinking LOW、プロンプトtask-plan-v3。公式google-genai 2.29.0、ADC、SDK HTTP attempts1、timeout30秒、最大出力2048tokens、temperature0を使用する。previewの提供条件は変わり得るため、永久に最良であるとは主張しない。2.5 Flashの公式退役日は2026-10-20であり、提出期限前の移行を考慮した。

出力を見る前に固定した24問題で比較し、安全に関わる18問題は100%、全体23/24以上を必須とした。未知地点拒否、順序、検査の有無、8手順の境界を平均点で隠さない。合格はこの固定題集での結果であり、任意入力に対する保証ではない。

5. 停止後の実RGB判定

判定器は実カメラRGBだけからred/green/unknownを返す。地点ID、期待色、world配色にはアクセスせず、赤は異常・緑は正常・不明は未確認とする。板はGazeboの衝突を持たない色面板であり、電気的LED・実機センサの測定ではない。

実到着後にpermitを撤回し、実SafetyStateがfalse、fresh odomが0.5wall秒連続停止となってから新しいフレームを待つ。receiptとstamp双方の鮮度は0.5秒以内。カメラ欠落・古い画像・3wall秒待機超時はunknown理由を記録し、ナビゲーションが健康なら残り手順を継続する。clock/scan/odom/TF/guardの故障は停止・中止する。stopやgeneration変更後の遅い画像結果は採用しない。

独立stub校正は0APIで実A赤/B緑画像を得て、ROIに灯面全体が入り床色が範囲外にあることを確認した。初期設定を変更せず、ROI=(.03,.10,.97,.64)、HSVの赤二範囲・緑範囲、S80/V50、最小連結面積2%、fill0.55、focus12等を正式前に固定した。全設定SHAはd03fa3824871b01fa28a2b66beedbc51e2fc5de4079ad9fa4ad840778db7a005。校正画像は正式採点に含めない。

校正用外部helperは製品Action完了後、初期sim時刻Noneの減算でrawfalseとなった。三到着と二PNGは確認済みだが例外後のpost2秒サンプルは未収集なので、その停止判定を成功としない。正式前に外部observerだけの有限clock-readyとNone安全処理を修正した。製品imageは不変で、49回帰が0skipで合格した。元のfixture失敗も保持した。

6. 実装上の工夫と検証可能性

参考実装の構成を発展させ、モデルの出力を四つの宣言的操作に限定した。モデル原文の根拠・地点・順序をローカル検証し、元の手順を固定実行器へ渡すことで、言語理解と運動制御の責任を分けた。到着はNav2の結果だけに依存せず、新鮮な位置とオドメトリ、連続停止を確認する。画像はその後に取得し、同じ地点の赤緑交換と灰色の未確認を別試験で検証した。

工夫実装と検証の対応
原計画の追跡原文・元JSON・検証済計画をActionとNav2のUUIDに結び付け、失敗をモデル・検証器・通信・実行に分ける
安全な実行境界独立した停止とpermit/新鮮度の監視を設け、取消終態が不明な場合は故障ロックする。停止後の旧応答を採用しない
地点設定と自己位置推定の分離人が設定したmap・命名座標・初期姿勢を用い、AMCLがレーザースキャンとodom/TFから自己位置を推定する。Nav2が現在位置から経路を計画する
判色の独立性地点名や期待色を使わず実RGBだけを分類。独立校正後に設定SHAを固定し、正式5画像で評価する
証拠の検証可能性原応答、画像、設定、実行ソースのSHAと実測値を保存し、校正・単体fixture・真正なオンライン試験を分ける

アプリ内の累積上限はUS$5または300試行で、80%で警告する。全プロセス・全モデルが同じSQLite policyを共有し、送信前に費用上界を原子的に予約する。正式三回終了時65試行、記録額US$0.414520は用量未知の保守予約0.166363と既知tokensによる価格推定0.248157の和であり、実請求額ではない。費用が不明な応答を0と扱わず、過去の失敗も記録に残した。

7. 考察と今後の課題

固定24題での意味検証24/24と、ロボット全体の信頼性は別である。先行オンラインP2の全タスク成功は1/3であり、速度命令の期限切れと返航時の進展失敗を残した。後続の正式視覚試験3/3タスク・5/5画像は、実画像から状態を記録して残り手順へ進む機能を示すが、一回の経路改善や少数画像から長期安定性を結論付けることはできない。

本実装は既存の学習済みGeminiによる言語推論を用い、この課題のための追加学習やSLAMは行っていない。静的地図、命名座標、初期姿勢と差動二輪モデルを事前設定する範囲で、自己位置推定・経路計画と画像確認を接続した。実機の電気的LED、異なる灯形・照明・反射・遮蔽、任意環境への一般精度は未検証である。今後は反復走行と独立した画像条件を増やし、保護停止や判別不能も含めた成功率を測ることが課題となる。
